# 功能 Spec：项目空间操作审计

文档编号：AL-FEAT-001 · 版本：1.0 · 日期：2026-09-07 · 状态：已实现，待业务评审

关联需求：AL-AUD-001、AL-AUD-002、AL-AUD-003、AL-AUD-004、AL-AUD-005、AL-AUD-006

关联：[产品规范](../product-spec.md) · [接口契约](../api-contract.md) · [验收矩阵](../acceptance.md)

## 1. 问题与目标

多人维护同一项目空间时，事务字段、依赖、成员或配置的变化需要可追溯。普通业务动态不足以覆盖空间管理、批量操作、撤销恢复和永久删除，也不能替代仅向管理员开放的审计查询。

本功能提供当前空间的编辑历史，回答四个核心问题：哪个账号进行了操作、执行了什么操作、影响了哪个对象、对象在操作前后是什么状态。

用户故事：作为项目空间管理员，我希望从头像菜单进入审计页面，按用户、对象、操作和时间查询记录，并查看历史快照，以便核对变更、排查误操作和交接项目。

## 2. 范围与非目标

范围包括网站 API 内已纳入审计的成功对象变更、管理员入口、筛选分页、前后快照和日志保留。记录起点为审计模块启用之后，不补造历史事件。

不包含登录安全事件、失败攻击记录、数据库外部直接修改、页面主题偏好、通用导出审计、快照内容全文搜索、审计 Excel 导出、独立日志平台、数字签名、外部时间戳或 WORM 存证。

## 3. 交互规格

### 3.1 入口与页面

1. 当前空间角色为 `admin` 时，在右上角头像菜单底部显示“审计”，位于“退出”之后。
2. 点击后进入主内容区域的独立审计视图，显示标题、当前空间名称、筛选区、结果表格与分页，不叠加工作台业务筛选。
3. “返回工作台”回到进入审计前的画布、表格或看板。
4. 切换空间、退出或失去管理员权限后清理审计数据；迟到的旧请求不得覆盖新页面。
5. 已归档空间仍可查询；普通成员入口隐藏且后端拒绝直接访问。

### 3.2 查询及快照

| 区域 | 内容与行为 |
| --- | --- |
| 筛选 | 完整用户账号、操作类型、对象类型、对象名称或 ID、开始和结束时间 |
| 操作 | 查询、重置、上一页、下一页；条件变化后从第 1 页查询 |
| 列表 | 操作时间、用户账号、操作类型、操作对象、查看快照 |
| 默认排序 | 操作时间倒序、记录 ID 倒序 |
| 默认分页 | 每页 25 条，展示总条数与页数 |
| 无结果 | “暂无符合条件的审计记录” |
| 加载及失败 | 显示查询中状态，翻页按钮暂时禁用；失败显示错误，可重新查询 |
| 快照弹窗 | 显示账号、对象名称与时间，双列显示操作前/后 JSON；窄屏单列 |
| 快照安全 | 用户内容作为文本显示；不得执行快照内 HTML 或脚本 |

## 4. 记录对象与操作分类

### 4.1 对象范围

| 对象代码 | 操作对象 | 快照范围 |
| --- | --- | --- |
| `workspace` | 项目空间 | 空间资料及归档状态 |
| `line` | 主线或支线 | 线字段、父线 ID、日期及删除状态 |
| `task` | 事务 | 业务字段、删除状态、前置事务 ID、图片和附件元数据 |
| `milestone` | 里程碑 | 业务字段、删除状态、验收事务 ID |
| `member` | 空间成员 | 账号资料、空间角色和加入时间，不含密码散列 |
| `settings` | 状态设置 | 状态列表及颜色配置；对象 ID 为 `statuses` |
| `comment` | 事务评论 | 评论正文、作者及事务 ID |
| `follow` | 事务关注关系 | 事务与用户关系，对象 ID 为 `task_id:user_id` |
| `account` | 本人账号 | 密码/头像相关操作的脱敏账号状态 |

关系或文件变更并入其所属事务/里程碑快照，不额外承诺每个文件都有独立审计行。业务对象名称与操作者账号按记录当时值保存，不能依赖当前关联对象仍然存在。

### 4.2 操作代码

| 代码 | 展示名称 | 适用操作 |
| --- | --- | --- |
| `create` | 新增 | 新建对象、建立成员等 |
| `update` | 修改 | 对象字段、依赖集合、文件集合或配置变化 |
| `delete` | 删除 | 软删除对象、移除成员等 |
| `import` | 导入 | 统一、线或事务 Excel 导入 |
| `bulk_update / bulk_delete` | 批量修改 / 批量删除 | 事务批量入口 |
| `undo / redo` | 撤销 / 重做 | 空间单步恢复 |
| `restore` | 恢复 | 回收站恢复、空间取消归档 |
| `purge` | 永久删除 | 清空回收站、永久删除空间 |
| `archive` | 归档 | 空间归档 |
| `comment` | 发表评论 | 评论请求及其关联变化 |
| `follow / unfollow` | 关注 / 取消关注 | 主动关注操作 |
| `password / avatar` | 修改密码 / 修改头像 | 本人账号操作 |

分类以请求操作为主，并对一般对象变更区分新增、修改、删除。一条请求可以影响多个对象，产生多条相同请求标识的记录；例如评论附带自动关注时，可以同时记录评论与关注关系变化。

## 5. 审计数据契约

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | integer | 审计记录主键 |
| `workspace_id` | integer | 归属空间；管理其他空间时记录在实际被操作空间 |
| `user_id` | integer | 操作者用户 ID |
| `username` | string | 操作发生时的账号，不用显示姓名代替 |
| `operation` | string | 操作代码 |
| `object_type` | string | 对象类型代码 |
| `object_id` | string | 对象稳定标识或联合标识 |
| `object_name` | string | 操作后名称；对象永久删除时取操作前名称 |
| `snapshot` | object | `before` 与 `after`，可附 `password_changed` |
| `created_at` | string | 记录生成时间，UTC、微秒精度；同一请求共享 |
| `request_id` | string | 同一次请求变更的关联标识，不是接口幂等键 |

快照状态规则：

- 新增：`before:null`，`after` 为新增对象。
- 修改：同时保存前后对象，不仅保存请求体中的 patch。
- 软删除：保存前后对象，操作后包含删除标志与批次。
- 永久删除：`before` 为删除前对象，`after:null`。
- 撤销/重做：新增一组表示本次恢复结果的记录，不覆盖此前记录。

说明性片段（省略未变化的业务字段）：

```json
{
  "username": "reviewer",
  "operation": "update",
  "object_type": "task",
  "object_id": "123",
  "snapshot": {
    "before": {"id": 123, "name": "接口联调", "status": "未启动"},
    "after": {"id": 123, "name": "接口联调", "status": "进行中"}
  }
}
```

“完整对象快照”不表示整个空间数据库的副本。关系以关联 ID 表示，文件用摘要代替二进制，秘密字段剔除。

## 6. 脱敏、留存与一致性

密码明文和密码散列不得写入审计；检测到账号密码变化时仅附带 `password_changed:true`。图片、附件、头像记录 MIME、字节数和 SHA-256 等元数据。账号 ID、姓名、评论及业务正文仍可能包含个人或项目敏感信息，因此审计继续受空间管理员权限保护。

审计写入与业务写入必须在同一数据库事务中完成，任何审计异常必须回滚业务。记录条件为成功请求且快照对象实际出现差异；若仅有更新日期等被采集字段变化，也可能形成修改记录。快照完全相同的请求不产生新记录。

数据库禁止 UPDATE/DELETE 审计记录，应用不提供编辑或清理入口。清空回收站或删除空间不能清除已有日志；空间删除后日志仍存数据库，但不由其他空间的查询页面暴露。当前无自动到期清理规则，保留周期与外部归档待另行决策。

该机制保障应用路径内的追踪及原子性，不对具有数据库文件和结构控制权的主体提供外部不可篡改保证。

## 7. 验收场景

| 场景 | Given / 前提 | When / 操作 | Then / 期望 |
| --- | --- | --- | --- |
| AC-AUD-001 | 当前空间管理员或普通成员已登录 | 打开头像菜单并尝试访问审计接口 | 管理员可见并可查；普通成员隐藏入口，接口 403 |
| AC-AUD-002 | 成员创建了事务 | 改名后管理员按该成员账号查询 | 至少能找到创建与修改记录，前后名称可核对 |
| AC-AUD-003 | 两个事务属于当前空间 | 一次批量修改优先级 | 每事务单独一行，共享 request_id，前后优先级正确 |
| AC-AUD-004 | 项目内有可撤销业务变更 | 撤销、重做，再删除并清空回收站 | 原日志不变，本次动作追加记录，永久删除后仍可查看旧快照 |
| AC-AUD-005 | 管理员同时属于空间 A/B | 在 B 请求 A 的审计详情 | 返回 404，列表不泄漏 A 的记录 |
| AC-AUD-006 | 事务包含附件或账号发生改密 | 查看相应快照 | 可核对元数据/摘要；没有文件二进制、密码或密码散列 |
| AC-AUD-007 | 条件能匹配多页记录 | 使用操作、账号、对象、时间筛选并翻页 | AND 筛选、倒序分页、生效条件与页码正确 |
| AC-AUD-008 | 审计写入被模拟故障阻断 | 创建业务对象 | 请求失败，业务对象和成功编辑日志均不落库 |
| AC-AUD-009 | 存在跨表导入及级联删除场景 | 导入、删除线、恢复批次 | 受影响对象按实际变化留痕；无效导入不留成功编辑日志 |
| AC-AUD-010 | 查询尚未返回或快照含 HTML 字符串 | 切换空间、退出，或打开快照 | 旧响应不覆盖当前页；HTML 作为文本显示 |

测试映射与已观察结果见 [验收矩阵](../acceptance.md)。以上场景不替代完整的安全、容量及灾备验收。

## 8. 实现关联与扩展要求

| 位置 | 责任 |
| --- | --- |
| `audit.initialize` | 表、索引及只追加触发器 |
| `audit.begin / capture` | 建立事务并采集操作前状态 |
| `audit.finish` | 采集操作后状态、分类、脱敏并提交 |
| `app.load_authenticated_context / finish_audit_request` | 请求生命周期接入 |
| `app.query_audit / audit_detail` | 当前空间管理员查询与详情 |
| `static/app.js` 中 `loadAuditPage / openAuditSnapshot` | 列表、分页、快照和异步状态保护 |

新增编辑 API 时，必须检查它是否进入审计端点集合、快照是否包含新增对象/字段、权限与归档策略是否正确，并新增相应验收用例。新增字段若包含凭据或秘密材料，应先定义脱敏规则，再加入快照。
